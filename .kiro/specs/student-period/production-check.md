# 本番での確認の手順（student-period）

> 作成：2026-10-29（タスク 3.1）
> `main` に入れて本番に出たあと、作者が実際のアカウントで行う。開いている本番のタブは閉じて開き直してから始める。

## 1. 使ったことのあるアカウント（年月をまだ入れていない）
1. ログインする → ダッシュボードが今までどおり出る（オンボーディングに戻されない）
2. 「プロフィール」タブ → 「入学年月」「卒業予定年月」が「未設定」と出る
3. 「編集する」→ 入学年月の「年」だけ選んで「保存する」→「年と月の両方を選ぶか、両方を空にしてください」と出て保存されない
4. 月も選び、卒業予定を入学と同じ年月にして「保存する」→「卒業予定は入学より後の年月にしてください」と出る
5. 卒業予定を入学より後にして「保存する」→ 表示が変わる
6. 3 秒以上待ってからログアウトし、もう一度ログインする → 入れた年月が残っている
7. 時間割・成績・最大時限が、操作の前と変わっていない

## 2. 新しいアカウント
1. オンボーディングに「入学年月（任意）」「卒業予定年月（任意）」の欄がある。年は今年の前後4年から選べる
2. 年月を入れずに「次へ進む」→ 進める
3. （別のアカウントか、データを消してから）入学年月を入れて進む → ダッシュボードのプロフィールに出る

## 3. AI に年月が送られていないこと（任意）
1. 年月を入れた状態で、開発者ツールの「ネットワーク」タブを開く
2. AI 相談（画面4）と成績のリアクション（画面7）を使う
3. `consultation`・`grade-reaction` の依頼の「ペイロード」を見て、`enrollmentYearMonth`・`expectedGraduationYearMonth` がないこと、相談と成績のリアクションが今までどおり表示されることを確かめる

## 開発環境で確かめたこと（2026-10-29）
- 年月の関数：18 項目（空・正しい組み合わせ・片方だけ・同じ年月・前の年月・前後4年・範囲の外の保存済みの年・表示）
- オンボーディング：14 項目、プロフィール：13 項目、AI の依頼：7 項目、全体の流れ：7 項目（Firebase を偽物にした試しの画面）
- `secure-and-stable` の画面の確認（保存・ピン・最大時限・科目の上限・全体の流れ）がすべて今までどおり通る
- スマートフォンの幅（390px）で、オンボーディングとプロフィールの年月の欄が切れずに表示される
