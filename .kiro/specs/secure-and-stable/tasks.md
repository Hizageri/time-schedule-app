## Implementation Notes
- 2.1：知らない鍵 ID のための公開鍵の取り直しは 60 秒に1回までにした（でたらめな鍵 ID の依頼で Google に何度も取りに行かないため）。制限中に知らない鍵 ID が来たら 401 ではなく `keys_unavailable`（503）を返す。鍵の入れ替え直後の正しい利用者をログアウトさせないため
- 2.2 など：`api/_lib/` は `.js` 付きで import するので、使い捨ての確認は `tsc`（NodeNext）でスクラッチに書き出してから Node で動かす
- 3.1：認証の失敗を応答（401・503・500）に変える処理は3つの窓口で同じなので、`api/_lib/auth.ts` に `authFailureResponse` として置いた。窓口の確認は、`api/` を `tsc` でスクラッチに書き出し、テスト用の鍵と差し替えた `fetch` で関数を直接呼ぶ（`harness-api.mjs`）。シラバスは作業フォルダ基準で読むので、プロジェクトのフォルダから動かす
