# 本番での確認の手順（secure-and-stable）

> 作成：2026-10-24（タスク 8.1）
> 開発環境ではできない確認（実際の Google ログイン、S2、S4）を、作者が本番で行うための手順。
> 開発環境（試しの画面）で確かめたことは、最後の「開発環境で確かめたこと」にまとめた。

## 0. 出す前の準備

1. **Firestore のルールを反映する**：`deployment.md` の「ルールの反映の手順」に従い、リポジトリの `firestore.rules` を Firebase の管理画面に貼り付けて「公開」する
2. **Vercel の環境変数を確かめる**：`GOOGLE_API_KEY`（または `GEMINI_API_KEY`）と `VITE_FIREBASE_*`（6個）があること。`VITE_FIREBASE_PROJECT_ID` が Firebase のプロジェクト ID と一致していること（AI 窓口のトークンの確認に使う。`FIREBASE_PROJECT_ID` は設定しなくてよい）
3. **サーバーとブラウザを同じデプロイで出す**：`main` へのマージで両方が同時に出る。サーバーだけ先に出すと、古い画面からの AI の依頼が 401 になる
4. デプロイが終わったら、ブラウザで本番 URL を開き直す（古い画面のキャッシュを使わないため。スマートフォンはタブを閉じて開き直す）

## 1. S4：Firestore のルール（Rules Playground）

`deployment.md` の「ルールの確認の手順（Rules Playground）」の表のとおりに試す。

- 自分の uid で `get`・`set` → 許可される
- 別の uid で `get`・`set` → 拒否される
- ログインしていない状態で `get` → 拒否される
- `/other/abc` など `users` の外 → 拒否される

## 2. 共通の確認 1〜6（2つのアカウントで）

`roadmap.md` の「共通の確認」の表を、**新しいアカウント**と**使ったことのあるアカウント**の両方で行う。特に次を見る。

| # | 見ること |
|---|----------|
| 1 | 使ったことのあるアカウントでログインすると、確定済みの時間割・成績・ピンがそのまま出る（初期値に戻らない） |
| 2 | 科目選択で 40 科目選んだあと、41 科目目を選ぼうとすると「一度に選べるのは 40 科目までです」と出て、選ばれない |
| 3 | AI 相談（4）で講評が出る（S2） |
| 4 | 時間割作成（5）で 5 パターンが出る。ピン留めした科目は、どのパターンでもピンのクラスになっている（S2） |
| 5 | 成績入力（7）でコマどり先輩の反応が出る（S2）。「新学期へ進む」で D・F の科目は修得済みに入らない |

| 追加 | プロフィールで最大時限を 11 にすると、ダッシュボードの表が 11 限まで出て、再読み込み後も保たれる。9・10 限の授業があるのに最大時限が小さいときは「N限の授業が表示の範囲（M限まで）の外にあります」と出る |

## 3. 安全性の確認

| # | 手順 | 期待すること |
|---|------|--------------|
| S1 | ターミナルで `curl -i -X POST https://<本番 URL>/api/consultation -H 'Content-Type: application/json' -d '{}'`（トークンなし）と、`-H 'Authorization: Bearer abc'`（壊れたトークン）を付けたものを送る | どちらも `401` と `{"error":"unauthenticated"}`。Vercel のログに `[Consultation API] 認証で断りました` が出て、Gemini を呼んだログが出ない |

## 4. うまくいかないとき

| 症状 | 見るところ |
|------|-----------|
| ログインしているのに AI の機能を使うとログイン画面に戻る | Vercel の `VITE_FIREBASE_PROJECT_ID` が Firebase のプロジェクト ID と一致しているか。Vercel のログに `wrong_project` が出ていないか |
| AI の機能で「なんか調子が悪いみてえだ」が続く | Vercel のログで 500（`server_misconfigured`：API キーかプロジェクト ID がない）か 503（`auth_unavailable`：Google の公開鍵が取れない）かを見る |
| 「保存データを読み込めなかった」が出る | Firestore のルールを公開したか。Rules Playground で自分の uid の `get` が許可されるか |

## 開発環境で確かめたこと（2026-10-24）

- AI 窓口（`api/` を直接呼ぶ確認）：トークンなし・壊れた・期限切れで 401、上限を超える入力・形の違う入力・知らない科目で 400、GET で 405、チャットは 410。どれも Gemini を呼ばない。正しい依頼では、プロンプトにシラバスの文章が入り、送られた文章は入らない。ピンはプロンプトに入り、無効なピンは入らない（S1・S3）
- 画面（Firebase を偽物に差し替えた試しの画面）：ログイン直後に保存しない、読み込みに失敗したら保存せず失敗の画面、保存は 3 秒まとめて丸ごと、ページが隠れる・閉じる・ログアウト・利用者の切り替えの前に保存、ピンの解除と「新学期へ進む」が再読み込みで戻らない、最大時限の変更が保たれる、41 科目目を選べない、ピンが 5 パターンと代わりの時間割で守られる、表示の範囲の外の知らせ、AI 窓口の 401 でログアウト・それ以外は先輩の文面
- `npm audit --omit=dev` 0 件、ビルドした JS に grpc・protobufjs が入っていない、アプリの `console.log` が出ない（S5・S6）
