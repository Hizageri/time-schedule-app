# Brief: first-run-ux-refresh

> 2026-10-22 注：この brief は予選（10/31）に向けて書いたもの。予選の前提（審査員・日程）は古い。着手するときに `roadmap.md`（2026-10-22 版）に合わせて見直す。もとの `core-bug-fixes` は `secure-and-stable` に統合した

## Problem

初めて使う人が、時間割を作るまでの途中で迷う。予選では、審査員が自分のアカウントで初回から触る場合がある。いちばん大事な場面で迷うと、AI とコマどり先輩の価値が伝わらない。

## Current State

- 画面の流れ：オンボーディング（1）→ 条件（2）→ 科目選択（3）→ アドバイス（4）→ 生成（5）→ ダッシュボード（6）→ 成績入力（7）
- 画面3（`CourseSelectionScreen`）でできること：学年・学期で絞った科目カードの選択、詳細モーダル（シラバス・口コミ・ピン留め）
- 画面5（`GeneratorScreen`）でできること：5パターンのプレビュー、Q 切替、重なりの赤表示、クラスの手動変更、一時退避。`empty-slot-search` のあとは空きコマ検索も加わる
- 具体的に「どこで迷うか」はまだ整理していない（requirements で洗い出す）
- 期間は約4日（10/27〜10/30）

## Desired Outcome

- 初めての人が、説明を受けなくても画面3と画面5を迷わず進めて、時間割を確定できる
- 画面3・5では、次に何をすればよいか（科目を選ぶ、ピン留めの意味、パターンの比べ方、空いているコマの埋め方、確定のしかた）が画面上で分かる
- ほかの画面（ログイン・1・2・4）は、説明文や導線の小さな改善で、3・5へ迷わずたどり着ける
- 画面の流れ（1〜8の順番・数）は変わらない

## Approach

画面の流れは保つ。最重要の画面（3 科目選択・5 生成）だけを作り直す。

`src-structure-migration` で画面から計算が出ているので、この spec は見た目（`pages/`・`components/`）を中心に触る。画面5は、`empty-slot-search` で入った空きコマ検索の入口も含めて作り直す。時間が足りないときは、先に移行の「余裕があれば」部分を削る。それでも足りなければ「ほかの画面の小さな改善 → 画面3の作り直し」の順で削り、画面5の作り直しは最後まで残す（`roadmap.md` の「遅れたときに削る順番」）。

## Scope

- **In**:
  - 画面3（科目選択）と、科目詳細モーダルの作り直し
  - 画面5（生成）の作り直し（空きコマ検索の UI を含む）
  - ログイン・画面1・2・4 の、説明文やボタンの文言などの小さな改善
  - 迷う点の洗い出し（requirements で行う）
  - 変わった仕様を steering（`product.md` の利用の流れ、`structure.md` の構成）に反映する
- **Out**:
  - 画面の流れの変更（画面の追加・統合・並べ替え）
  - ダッシュボード（6）・成績入力（7）・振り返り（8）の作り直し
  - 動きの変化を伴う修正（`core-bug-fixes` の範囲）
  - 新しい機能の追加
  - 新しい UI ライブラリの導入（今の Tailwind・framer-motion・lucide-react で作る）
  - コマどり先輩のキャラ付けを変えること

## Boundary Candidates

- 画面3と科目詳細モーダルの見た目と導線
- 画面5の見た目と導線（パターンの比較、調整、空きコマ検索、確定）
- 共通の UI 部品（`components/`）の見直し：ボタン、ヘッダー、説明の出し方
- ほかの画面の文言の改善

## Out of Boundary

- 計算や通信のロジック（`hooks/`・`utils/`・`services/`）は原則として変えない。必要なら spec の変更として提案する
- 空きコマ検索の候補の条件（`empty-slot-search` が持つ）

## Upstream / Downstream

- **Upstream**:
  - `src-structure-migration`：見た目とロジックが分かれていること
  - `core-bug-fixes`：正しく表示・保存されること
  - `empty-slot-search`：画面5の空きコマ検索
- **Downstream**: 予選の後のダッシュボード・成績入力の見直し、全国展開に向けた UI

## Existing Spec Touchpoints

- **Extends**: なし
- **Adjacent**: `empty-slot-search`（画面5を共有する。この spec は見た目、向こうは仕組みを持つ）

## Constraints

- 画面の流れは保つ
- 色は `tailwind.config.js` のトークンを使う
- コンポーネントから `firebase/*`・`services/` を直接使わない
- UI の文言は日本語。コマどり先輩のキャラ付けを保つ
- 予定：10/27〜10/30（約4日）。10/31 の予選の前に、本番 URL で初回ログインからの流れを確認する時間を取る
