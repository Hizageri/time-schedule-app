# ADR-0004：開発を2段階に分ける（安全性と不具合の修正を先に、構成の移行は提出の後）

- 状態：採用
- 日付：2026-10-22
- 関係する spec：`secure-and-stable`（第1段階）、`src-structure-migration` ほか（第2段階）
- 出典：`.kiro/steering/roadmap.md`「Overview」「Approach Decision」「Constraints」

## 背景

約1週間後（2026-10-29 ごろ）にインターン先へ提出する。目標は「安全で正常に動くこと」（最優先）と「全国展開を前提にした設計」の2つ。実装は一人（＋Claude）で、テストがないので決まった段階で手による確認が要る。前の計画では、フォルダ構成の移行だけで4〜6日かかる見込みだった。

## 選択肢

### 案A：2段階に分ける
- 概要：第1段階（〜10/29）は `secure-and-stable`（安全性＋既知の不具合の修正）を今の構成のまま行う。第2段階（提出後）は、移行 → 全国展開向けのデータ設計 → DB 化 → 空きコマ検索 → UI の順に1つずつ進める
- メリット：1週間で「安全・正常に動く」を確実に終えられる
- デメリット：第1段階で直した場所を、第2段階の移行でもう一度動かす

### 案B：前の計画どおり、構成の移行から始める
- 概要：先に `src/` を目標の構成にしてから直す
- メリット：構成がきれいになってから直せる
- デメリット：1週間では移行で終わる可能性が高い

### 案C：第1段階は安全性だけにする
- 概要：不具合の修正は後回しにする
- メリット：確実に間に合う
- デメリット：データが消える不具合が残る

## 決めたこと

案A。

## 選ばなかった理由

- 案B：提出時に安全性の穴と、データが消える不具合が残る
- 案C：データが消える不具合が残り、「正常に動く」を満たさない
- 前の版の案B（2026-10-13、予選に向けて移行を先に行う）：予選がなくなり、優先順位が変わったため置きかえた

## 結果

- 良くなること：提出先が最初に気にする「安全面」と「データが消えないこと」を期限内に満たせる。全国展開向けのデータ設計を空きコマ検索や UI より先に置くので、後から作る機能が会津大学専用の前提に乗らない
- 受け入れたトレードオフ：手戻り。小さくするため、第1段階で新しく書く判定や計算は、移行先（`utils/` など）にそのまま移せる形にした
- 見直す条件：記録なし。遅れたときに削る順番（ピンの AI への反映 → 合格の判定の統一 → 6限より後の表示）は決めてあった
