# ADR-0003：サーバー側は PHP を使わず、Vercel の Node.js 関数（TypeScript）で書く

- 状態：採用
- 日付：2026-10-22
- 関係する spec：なし（全体の方針）
- 出典：`.kiro/steering/tech.md`「技術上の決まり」、`.kiro/steering/roadmap.md`「Scope（Out）」「Constraints」

## 背景

サーバー側の処理（AI 窓口）をどの言語・実行環境で書くかを決める必要があった。すでに `api/*.ts`（Vercel Serverless Functions、Node.js）で AI 窓口が動いていた。

## 選択肢

### 案A：Vercel の Node.js 関数（TypeScript）
- 概要：今の `api/*.ts` のまま。1ファイルが1エンドポイントになる
- メリット：フロントと同じ TypeScript で書ける。Vercel が標準で対応している。既存のコードをそのまま使える
- デメリット：特になし（記録なし）

### 案B：PHP
- 概要：PHP でサーバー側を書く
- メリット：記録なし
- デメリット：記録なし

## 決めたこと

案A。PHP は使わない。

## 選ばなかった理由

- 案B：記録には「方針として使わない」とだけ書かれていて、理由は書かれていない（作者に確認して書き足す）

> 補足（記録にない技術的な説明）：Vercel の公式の実行環境は Node.js・Python・Go・Ruby などで、PHP はコミュニティの runtime（`vercel-php`）を使う形になる。また、フロントとサーバーで言語が分かれると、型（`api/_lib/http.ts` のリクエスト・レスポンスの型など）を同じ言語で書けなくなる

## 結果

- 良くなること：フロントとサーバーが TypeScript に統一される。デプロイが Vercel だけで済む
- 受け入れたトレードオフ：記録なし
- 見直す条件：記録なし
