# ADR-0009：入学・卒業予定年月は `"YYYY-MM"` の文字列で持つ

- 状態：採用
- 日付：2026-10-29
- 関係する spec：`student-period`
- 出典：`.kiro/specs/student-period/research.md`「Decision: 年月は "YYYY-MM" の文字列で持つ」「年月の入力欄」、`.kiro/steering/data-model.md`

## 背景

プロフィールに、任意の入学年月・卒業予定年月を足す。将来、就職・インターンで企業とつなぐときの土台にする。保存する値の型と、入力欄の作りを決める必要があった。

## 選択肢

### 案A：`"YYYY-MM"` の文字列。未設定は `''`
- 概要：`enrollmentYearMonth: string`（例 `"2026-04"`）
- メリット：今の `userProfile` の項目（`nickname` など）と同じ string で、初期値も `''` にそろう。ゼロ埋めした `"YYYY-MM"` は辞書順と時系列が一致するので、文字列のまま前後を比べられる（`"2026-04" < "2030-03"`）
- デメリット：形が正しいかの確かめが要る

### 案B：`{ year: number; month: number } | null`
- 概要：年と月を数値で持つオブジェクト
- メリット：型で「年と月がある」ことを表せる
- デメリット：ほかのプロフィールの項目と形が違う。未設定が `null` になり、初期値の扱いが他の項目と変わる

## 決めたこと

案A。形の確かめと前後の判定は `src/utils/studentPeriod.ts` の `validateStudentPeriod` で行う。入力欄は年と月の `<select>` 2つ（年は今年の前後4年）。

## 選ばなかった理由

- 案B：ほかのプロフィールの項目とそろわず、初期値や比較の扱いが増える。比べるだけなら文字列で足りる

## 結果

- 良くなること：型と初期値がほかの項目とそろう。比較が単純
- 受け入れたトレードオフ：`"2026-4"` のような崩れた値を防ぐ確かめが必要（関数1つにまとめた）
- 入力欄について：`<input type="month">` はブラウザによってカレンダーが出ず文字入力になるので、どこでも同じに動く `<select>` 2つにした
- 見直す条件：記録なし
