# ADR-0016：学期ごとに保存場所を分け、選んだ科目は年度つきの科目 ID で持つ

- 状態：提案（`university-data-model` の設計で決める）
- 日付：2026-11-06（論点と比較を記録）
- 関係する spec：`university-data-model`、`course-history`、`syllabus-db`（ADR-0014）
- 出典：作者への聞き取り（2026-11-06）、`.kiro/steering/roadmap.md`（`university-data-model`）、ADR-0008・ADR-0015

## 背景

ADR-0015 の形では、「新学期へ進む」で前の学期の時間割と成績が消える。roadmap の `university-data-model` には次の変更が書かれている。

1. 大学を名前ではなく ID で持つ（`"会津大学"` → `universityId: "u-aizu"`）
2. 選んだ科目を、シラバスのコピーではなく年度つきの科目 ID（例：`"u-aizu/2026/HS01"`）だけで持つ
3. 学期ごとに保存場所を分け（例：`users/{uid}/terms/{学期ID}`）、前の学期の時間割・成績を消さずに履歴として残す

作者の理由：

> 前の学期の時間割や成績を、消さずに履歴として残したい。ただ、全部を1つのドキュメントに入れると、ログインや保存のたびに過去の学期の分まで読み書きすることになる。なので学期ごとに分けて、ふだんは今の学期に必要な情報だけを読み書きし、過去の学期は必要なときだけ読む形にしたい。

## 選択肢（保存場所の分け方）

### 案A：今のまま1ドキュメント（ADR-0015）
- メリット：read・write が1回ずつ。常に atomic。security rules が単純
- デメリット：履歴を残すとドキュメントが年々大きくなり、毎回全部を読み書きする。過去の学期だけを読めない
- 要件との適合：履歴を残す要件（course-history・成績の蓄積）に合わない

### 案B：利用者のドキュメント ＋ 学期ごとのサブコレクション
- 概要（項目の分け方は Claude の案。設計で決める）：
  - `users/{uid}`：プロフィール・設定・今の学期の ID（`currentTermId`）
  - `users/{uid}/terms/{termId}`：その学期の条件・選んだ科目・確定した時間割・成績・ピン・教室名
  - 「新学期へ進む」は、今の学期を消すのではなく、新しい学期のドキュメントを足して `currentTermId` を付け替える
- メリット：過去の学期を消さずに残せる。ログイン時に読むのは「利用者 ＋ 今の学期」の2つだけ。1ドキュメントの大きさが学期1つ分に収まる
- デメリット：「新学期へ進む」で複数のドキュメントを書くので、batch write で atomic にする必要がある。security rules に下の階層の match が要る（今のルールでは拒否される）。ADR-0008 の「丸ごと書く」をドキュメントごとに考え直す
- 要件との適合：高い

### 案C：もっと細かく分ける（成績・時間割・ピンを別々のコレクションにする）
- メリット：変わった部分だけ書ける。項目ごとに検索できる
- デメリット：read・write の回数が増える。時間割と成績がずれないようにするのが難しい
- 要件との適合：低い。利用者をまたいだ検索や項目ごとの検索をしない

### 案D：ブラウザ（localStorage）だけに保存する
- メリット：DB が要らない
- デメリット：端末をまたげない。ブラウザのデータを消すと全部消える
- 要件との適合：低い

### 別の軸：選んだ科目をコピーで持つか、ID で持つか

| | コピーで持つ（今） | 年度つきの ID で持つ |
|---|---|---|
| メリット | シラバスが変わっても、そのとき取った科目の中身が残る | ドキュメントが小さい。重複がない |
| デメリット | ドキュメントが大きい。シラバスを直してもコピーは古いまま（stale） | 引くときにシラバスを読む必要がある（ADR-0014） |

年度ごとのシラバスを書き換えずに残せば（immutable）、ID で持っても「そのとき取った科目の中身」は変わらない。

## 決めたこと

まだ決めていない。Claude の推奨は **案B ＋ 年度つきの科目 ID**。`university-data-model` の設計で決める。
