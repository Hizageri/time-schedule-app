# ADR-0010：`src/` を役割ごとのレイヤー（pages・hooks・services・utils・config など）に分ける

- 状態：採用
- 日付：2026-10-13（目標の構成を決定）、2026-10-30（`config/` を追加し、移行を完了）
- 関係する spec：`src-structure-migration`
- 出典：`.kiro/steering/structure.md`「目標の構成」「各フォルダのルール」「依存の向き」、`.kiro/specs/src-structure-migration/brief.md`「Problem」、`.kiro/specs/src-structure-migration/research.md`

## 背景

移行の前の `src/` は `logic/`・`ai/`・`ui/`・`components/` に分かれていたが、画面ファイルに計算と状態の操作が直接書かれていた（`DashboardScreen.tsx` 663 行、`GeneratorScreen.tsx` 479 行、`AppContext.tsx` 347 行）。学期・クォーターのビット判定は計9か所、コマ表のセル探しは2か所に重複していた。後続の spec（`university-data-model`・`empty-slot-search`・`first-run-ux-refresh` など）がこれらを触るので、同じ修正を何か所にも入れて漏れる恐れがあった。

## 選択肢

### 案A：役割ごとのレイヤーに分け、依存の向きを決める
- 概要：`pages/`・`components/`（見た目）→ `hooks/`・`context/`（裏側の処理・共有する状態）→ `services/`（通信）・`utils/`（純粋関数）・`config/`（設定値）・`lib/`（ライブラリの設定）・`data/`。上から下へだけ import する。`firebase/*` は `lib/`・`hooks/`・`context/` だけ
- メリット：責務の境界がはっきりする。計算を1か所にまとめられる。画面を作り直すときに、ロジックを触らずに済む
- デメリット：ファイルとフォルダが増える。移行の作業がいる

### 案B：今の構成のまま、必要なところだけ直す
- 概要：重複だけをまとめ、フォルダは変えない
- メリット：移行の作業がいらない
- デメリット：画面にロジックが残り、後続の spec のたびに大きな画面ファイルを触る

> 補足（記録にない比較）：ほかに feature-based（機能ごとのフォルダ）の構成もある。2026-10-13 の決定では比較が記録されていない

## 決めたこと

案A。移行は専用の spec（`src-structure-migration`）で、見た目と動きを変えずに3段階で行った（型・計算・通信・状態 → 重複のまとめと hooks → UI 部品）。設定値は作者の判断で `config/` を新しく足した（2026-10-30）。

## 選ばなかった理由

- 案B：後続の spec が触る計算（特にビット判定。`university-data-model` で大学ごとの設定にする）が散らばったままだと、修正の場所が多くて漏れやすい
- 移行を一度に行う案：動きが変わったときに原因を絞れないため、段階に分けた

## 結果

- 良くなること：ビット判定が `utils/targetBit.ts`、セル探しが `utils/timetable.ts` の1か所になった。画面3・5・6の裏側の処理が `hooks/` に分かれた。Firestore 同期が `hooks/useUserDataSync.ts` に分かれた
- 受け入れたトレードオフ：ファイル数の増加。GPA シミュレーターやプロフィールの編集などの計算は、まだ画面に残っている（`structure.md`「画面に残っている計算」）
- 確かめ方：試しの画面の 122 件（動き 100 件・画面の HTML の比較 22 件）が移行の前後で同じに通った（ADR-0011）
- 見直す条件：記録なし

## 聞かれたときの答え方

> Q. なぜこのディレクトリ構成にしたのですか？

画面ファイルに計算や状態の操作が直接書かれていて、同じビット判定が9か所に重複していました。次に「学期制などを大学ごとの設定にする」作業があるので、判定が散らばっていると直す場所が多くなります。そこで、見た目・裏側の処理・通信・純粋な計算・設定をレイヤーに分け、依存は上から下へだけと決めました。移行は見た目と動きを変えないことを条件に、3段階に分けて、各段階で自動の確認を通しています。
