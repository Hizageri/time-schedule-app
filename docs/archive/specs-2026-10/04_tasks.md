## 付録：課題一覧

> 確度：**確定** = コードとデータから確実 / **要確認** = 実際に動かして再現を確かめたい

### 🔴 セキュリティ（最優先）

#### S1. Gemini APIキーが GitHub の履歴に残っている【✅ 対応済み 2026-10-07】
- 2026-10-07：新しいキーを Vercel に設定して Redeploy。古い3つのキー（末尾 9fd0 / mgqA / pJBE）を削除。AI機能の動作を確認済み
- 2026-03-21 のコミット（`e47b245` 〜 `b2367fc`）で `.env` が commit されていて、本物のキーが**2種類**入っている
- 後のコミットで `.env` を削除しているが、**履歴からは消えていない**。公開リポジトリなので誰でも見られる
- 対応：Google AI Studio（または Google Cloud Console）で**両方のキーを無効化**し、新しいキーを Vercel の環境変数に設定する。履歴を書き換えるより、キーを無効化するほうが確実

#### S2. `/api/*` に認証がない【確定】
- URL を知っていれば誰でも Gemini を呼べるので、あなたの API の利用枠が消費される
- 対応案：リクエストに Firebase の ID トークンを付け、サーバー側で検証する

#### S3. Firestore のセキュリティルールがリポジトリにない【一部対応 2026-10-07】
- 2026-10-07：Firestore の `(default)` データベースを作成し、`users/{uid}` を本人だけが読み書きできるルールを Firebase コンソールで設定済み
- 残り：ルールを `firestore.rules` としてリポジトリで管理する
- Firebase コンソールで `users/{uid}` を本人しか読み書きできない設定になっているか確認する
- 確認後、`firestore.rules` としてリポジトリで管理する

### 🟠 バグ

#### B1. 「OT03-001 大規模分散Webインフラ構築入門」の詳細を開くとアプリが落ちる【確定】
- `syllabus.json` のこの科目だけ、`classes` の中に科目オブジェクトが入れ子になっていて、`class_id` と `schedule` がない
- `target_bit=655`（1〜4年・通年）なので、ほぼ全員の科目一覧に表示される
- 詳細モーダルの `cls.schedule.join()` が TypeError → エラー境界（Error Boundary）がないので**画面が真っ白**になる。選択して時間割生成に進んだ場合も同じ
- 対応：データを直す。あわせて、JSON 読み込み時の形チェックと Error Boundary を入れる

#### B2. 6限以降の授業が時間割に表示されない【確定】
- 最大時限の初期値は 5 だが、データでは **204科目中140科目**が6〜10限にコマを持つ（11限もある）
- 時間割グリッドは `maxPeriods` までしか描画しないので、6限以降の授業は**グリッドにも集中講義欄にも出ず、消えたように見える**
- 対応案：初期値を 10 にする。または、選んだ科目に合わせて行数を自動で決める

#### B3. 「受講クラス希望（固定）」が時間割生成に反映されない【確定】
- 詳細モーダルで固定したクラス（`pinnedClasses`）を `/api/timetable-patterns` に送っていない。生成後の初期割り当てでも参照していない
- 同じく、稼働曜日と最大時限も AI に送っていない

#### B4. ログイン直後に保存データが初期値で上書きされる可能性【要確認】
- ログイン時は `setUser()` が先に走り、Firestore の読み込みを待つ間に「状態が変わったら保存」の effect が初期状態（`defaultState`）を書き込む
- 書き込みと読み込みのタイミングによっては、プロフィールや時間割が初期値に戻る
- 再現手順の案：データを作る → ログアウト → ログイン → 中身が残っているか確認
- 対応案：読み込みが終わるまで保存しないフラグ（`hydrated`）を入れる

#### B5. 新学期にリセットしても、古い成績や固定クラスが復活する可能性【要確認】
- 保存は `setDoc(..., { merge: true })` で行っている。merge では、Map の中のキーを消したり `grades: {}` で空にしたりしても、Firestore 側の既存のキーは消えない
- 対応案：`merge` を使わず全体を上書きする。またはリセット時に `deleteField()` を使う
- 再現手順の案：成績を入力 → 新学期へ → リロード → 成績タブを確認

#### B6. 時間割の重なり判定の演算子の優先順位ミス【確定・ただし現在は未使用】
- `utils.ts` の `(existing.targetBit ?? 0 >> 6) & 3` は `targetBit ?? (0 >> 6)` と解釈されるので、Q ではなく学年ビットを見てしまう
- 正しくは `((existing.targetBit ?? 0) >> 6) & 3`
- 関数自体は今どこからも呼ばれていないが、重なりチェックを実装するときにそのまま使うと誤判定する

#### B7. AI 生成に失敗すると、5パターンが全部同じになる【確定】
- 失敗時のフォールバックは割り当てが空なので、全科目が `classes[0]` で埋まり、5つとも同じ時間割になる
- 時間の重なりの検証もしていない（プレビューで赤く表示するだけ）
